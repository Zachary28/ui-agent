# Midscene UI Agent 中文使用手册

## 1. 系统定位

Midscene UI Agent 是一个 Python UI 自动化运行时。它用统一领域契约描述任务，以 LangGraph 编排运行、Loop、checkpoint 和恢复，通过平台适配层调用官方 Midscene CLI，并统一生成事件、证据、结果和 manifest。

第一版已接入：

- Browser：Puppeteer、CDP、Bridge。
- Computer：Windows RDP。
- Android：ADB，可指定设备和应用 URI。
- iOS：WebDriverAgent。
- HarmonyOS：HDC。
- Vitest E2E：Web、Android、iOS 测试工程生命周期。

所有 live 操作直接执行，不存在审批或 `--approve` 流程。调用方必须用 plan 模式预览，并用 Loop 退出条件限制长时间任务。

## 2. 架构与目录

依赖方向为 `interfaces -> application -> domain`，平台与基础设施实现依赖 domain，不允许 domain 反向导入平台、基础设施或接口层。

```text
src/midscene_ui_agent/
  interfaces/                 CLI 与 Python API
  application/
    graphs/                   主图、单操作子图、Loop 子图
    generation/               测试生成协议与 Python/YAML 渲染器
    nodes/                    配置、生命周期、执行、报告节点
    services/                 skill、handler、Loop 平台绑定
    workflows/orchestrator.py 依赖构造、图调用、结果映射
  domain/
    contracts/                请求、结果、Loop、指纹、测试用例契约
    policies/                 退出、重试、恢复幂等策略
    runtime/                  JSON 可序列化图状态
  infrastructure/            配置、命令、证据、SQLite、报告
  platforms/                 六个平台的 canonical adapter
  config/                    wheel 内置分层配置、schema、skill lock
tests/
  unit/                       不需要真实 UI
  integration/                显式启用的 Web/Android 实测
  distribution/              安装后 wheel 冒烟
```

PlantUML 图位于 `docs/diagrams/`。

## 3. 部署

### 3.1 必需依赖

- Python 3.11 或 3.12。项目声明支持 3.11+；CI 固定验证 3.11/3.12。
- Node.js 18+，包含 npm 和 npx。
- 可访问 npm registry 和模型 API。
- 平台工具：Android 使用 adb，iOS 使用 WDA，HarmonyOS 使用 hdc，Computer 使用 RDP，Vitest E2E 使用 pnpm。

Midscene 不需要写入 Python 依赖，也不要求在本项目执行 `npm install`。适配器执行 `npx -y @midscene/web@1`、`@midscene/android@1` 等官方包；首次运行会下载并缓存。

### 3.2 安装源码版

```powershell
cd D:\agent\ui-skill\ui-agent-python
python -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

生产环境可构建 wheel：

```powershell
python -m build
python -m pip install dist\midscene_ui_agent-0.1.0-py3-none-any.whl
```

wheel 包含 `config/defaults.yaml`、平台/应用/任务 YAML、两个 JSON schema 和 `skills.lock.json`。

### 3.3 模型配置

编辑 `.env`：

```ini
MIDSCENE_MODEL_API_KEY=your-key
MIDSCENE_MODEL_NAME=your-model
MIDSCENE_MODEL_BASE_URL=https://your-compatible-endpoint/v1
MIDSCENE_MODEL_FAMILY=your-model-family
```

源码入口会加载当前目录的 `.env`；若不存在则读取 `.env.example`。已经存在的进程环境变量优先，不会被文件覆盖。不要把 key、Cookie、密码、WDA session、Authorization header、手机号或验证码放入 YAML、prompt、checkpoint 或报告。

### 3.4 环境检查

```powershell
python --version
node --version
npm --version
npx --version
midscene-ui-agent run --platform android --check-dependencies
```

Android：

```powershell
adb devices
# AGYJUT3628001141    device
```

Browser：Chrome 可以由 Puppeteer 启动，也可传 `--cdp` 连接已启动实例。

## 4. CLI

### 4.1 plan 与 live

`plan` 是默认模式，仅写 `plan.json`，不调用平台 CLI。`live` 构建 LangGraph 并执行真实 UI 操作。

```powershell
midscene-ui-agent run --platform browser --url https://example.com --goal "检查标题"
midscene-ui-agent run --platform browser --url https://example.com --goal "检查标题" --mode live
```

### 4.2 直接请求

```powershell
# Browser
midscene-ui-agent run --platform browser --url https://example.com `
  --goal "截取页面" --operation screenshot --mode live

# Android
midscene-ui-agent run --platform android --device-id AGYJUT3628001141 `
  --goal "截取当前屏幕" --operation screenshot --mode live

# Android 启动应用
midscene-ui-agent run --platform android --device-id AGYJUT3628001141 `
  --launch-uri com.tencent.qqlive --goal "启动腾讯视频" --operation launch --mode live
```

常用目标参数包括 `--url`、`--device-id`、`--launch-uri`、`--cdp`、`--bridge`、`--wda-host`、`--wda-port`、`--project-dir` 和 `--vitest-platform`。`--json` 输出完整 `AutomationResult`。

### 4.3 配置式运行

```powershell
midscene-ui-agent run `
  --platform android `
  --app android.tencent-video `
  --task watch-free-series `
  --environment local `
  --device-id AGYJUT3628001141 `
  --mode live `
  --override "loop.exit_conditions.max_runtime_seconds=900" `
  --override "loop.operations.switch_episode.interval_seconds=120"
```

配置式运行必须同时给出 `--platform --app --task`。任务提供 `goal.prompt` 时 `--goal` 可省略；自定义任务若没有 goal，必须通过 `--goal` 补充。`--config-root` 可指向同结构的外部目录。

### 4.4 恢复

纯恢复从 `--report-dir/langgraph.sqlite` 读取请求和指纹：

```powershell
midscene-ui-agent run --resume <run_id> --report-dir ./artifacts
```

配置式恢复重新解析当前配置：

```powershell
midscene-ui-agent run --resume <run_id> --platform android `
  --app android.tencent-video --task watch-free-series `
  --device-id AGYJUT3628001141 --mode live
```

恢复时只给部分 selector 会被拒绝。修改目标、goal、environment、override 或 skill lock 会重新计算指纹；不匹配返回 `resume_invalid`，并在连接平台之前停止。

## 5. Python API

### 5.1 直接运行

```python
from midscene_ui_agent.domain.contracts import AutomationRequest
from midscene_ui_agent.interfaces.api import run

request = AutomationRequest(
    platform="browser",
    target={"url": "https://example.com"},
    goal="验证标题可见",
    operation="assert",
    mode="live",
    report_dir="./artifacts",
    run_id="browser-title-001",
)
result = run(request)
```

### 5.2 配置式运行

```python
from midscene_ui_agent.interfaces.api import run_configured

result = run_configured(
    platform="android",
    app="android.tencent-video",
    task="watch-free-series",
    target_overrides={"device_id": "AGYJUT3628001141"},
    overrides=["loop.exit_conditions.max_runtime_seconds=600"],
    mode="live",
)
```

### 5.3 恢复

```python
from midscene_ui_agent.interfaces.api import resume_run

result = resume_run("browser-title-001", report_dir="./artifacts")
```

测试可注入 `runner` 或 `adapters`，避免调用真实外部命令。生产代码不应导入 application graph 的内部节点。

## 6. 分层配置

默认根目录由 `importlib.resources` 定位，因此源码、editable install 和 wheel 使用同一份配置：

```text
defaults.yaml
platforms/<platform>.yaml
apps/<platform>/<name>.yaml
tasks/<task>.yaml
environments/<environment>.yaml
```

合并顺序：defaults、platform、app、task、environment、runtime override。映射深度合并，标量和列表替换；列表追加需使用 `{append: true, values: [...]}`。以下输入在执行前报错：

- 未知 override 路径。
- 修改 `platform`、`id`、`profile` selector。
- task 引用了错误 app。
- app 平台与 CLI 平台不一致。
- Loop 字段类型或约束不合法。

结构化 goal 的 `category` 和 `require_free` 会进入 `switch_episode.params`；显式 operation param override 的优先级更高。

## 7. Loop Engineering

主图把 Loop 作为 LangGraph 子图执行。调度支持固定间隔、启动触发、弹窗、广告、卡顿、指定运行时间和前置操作完成触发。

```yaml
loop:
  defaults:
    interval_seconds: 5
    min_operation_interval_seconds: 1
    timeout_seconds: 30
    max_attempts: 3
    evidence: true
  operations:
    dismiss_popup:
      enabled: true
      interval_seconds: 2
      priority: 100
      on_popup: true
    skip_ad:
      enabled: true
      interval_seconds: 1
      priority: 90
      on_ad: true
    check_playback:
      enabled: true
      interval_seconds: 5
    switch_episode:
      enabled: true
      interval_seconds: 300
      strategy: next_episode
      params:
        require_free: true
  exit_conditions:
    max_runtime_seconds: 1800
    max_switches: 3
    max_consecutive_failures: 3
    max_no_progress_ticks: 5
    disconnect_on_exit: true
```

每项操作的 timeout、attempts、interval 和 priority 独立生效。Loop 支持关闭弹窗、跳广告、播放/检查/恢复、切集、滑动、截图、断言、返回和报告快照。登录和付费提示不会被绕过，而是触发退出条件。

## 8. LangGraph 与恢复语义

主图节点顺序：

```text
prepare_run -> verify_skill_lock -> execute_route -> finalize_run
                                  |-> single-operation subgraph
                                  `-> Loop subgraph
```

`run_id` 同时是 LangGraph `thread_id`。新运行会删除同 thread 的旧 checkpoint，避免继承旧 artifacts、error、游标或释放状态；`resume=True` 使用 `graph.invoke(None)` 从现有状态继续。

恢复比较以下指纹：

- `config_hash`
- `profile_hash`
- `loop_plan_hash`
- `skill_lock_hash`
- `target_fingerprint`

幂等操作可安全重试；切集和滑动等非幂等操作先调用 `verify_effect`，已生效时标记完成，避免重复副作用。

## 9. Skill Lock

运行时仅在提供 skill root 时校验所选平台涉及的 skill 文件：

```powershell
midscene-ui-agent run ... --skills-root ..\midscene-skills `
  --skills-lock .\src\midscene_ui_agent\config\skills.lock.json
```

只传 `--skills-lock` 不传 `--skills-root` 是配置错误。`skills verify`/`skills lock` 命令用于完整目录校验或生成锁；运行图的校验发生在连接 UI 前。

## 10. 报告与证据

```text
artifacts/
  langgraph.sqlite
  checkpoints.sqlite
  <run_id>/
    plan.json                 plan 模式
    result.json
    manifest.json
    events.jsonl
    evidence/
    work/
      midscene_run/report/   Midscene HTML 与截图
      midscene_run/log/      原生日志
```

manifest 只记录 hash、thread ID、graph phase 和相对产物路径，不写 live adapter、连接对象或密钥。每个操作使用稳定 operation ID，证据文件区分 before/after。资源释放错误追加到 `secondary_errors`。

## 11. 测试脚本生成接口

领域层提供 `TestCaseSpec` 和 `TestStepSpec`；application 层提供 `TestScriptGenerator`、`TestScriptRenderer` 协议以及确定性的 Python/YAML renderer。模型生成器只需实现协议，不应直接依赖 orchestrator 或 LangGraph state。

```python
from midscene_ui_agent.application.generation import PythonTestRenderer, YamlTestRenderer
from midscene_ui_agent.domain.contracts import TestCaseSpec, TestStepSpec

spec = TestCaseSpec(
    name="open_example",
    platform="browser",
    target={"url": "https://example.com"},
    steps=[TestStepSpec(action="run", prompt="验证页面标题")],
    assertions=["标题可见"],
)
python_source = PythonTestRenderer().render(spec)
yaml_source = YamlTestRenderer().render(spec)
```

相同 spec 始终生成相同文本；Python 只导入公开接口并可直接编译，YAML 使用安全序列化且支持 Unicode。

## 12. 平台注意事项

| 平台 | Midscene 包/方式 | 关键字段 |
|---|---|---|
| browser | `@midscene/web@1` | `url`, `cdp`, `bridge`, headers |
| computer | `@midscene/computer@1` | `host`, `username`, `password_env`, RDP 参数 |
| android | `@midscene/android@1` | `device_id`, `app_uri`, `use_scrcpy` |
| ios | `@midscene/ios@1` | `wda_host`, `wda_port`, `session_id` |
| harmony | `@midscene/harmony@1` | `device_id`, `app_uri` |
| vitest_e2e | Vitest + Midscene | `project_dir`, `vitest_platform` |

目标字段由 Pydantic 校验。例如 Android 的 run/screenshot/assert 需要 `device_id`，iOS connect 需要 WDA host/port，Vitest update/debug 需要 `test_name`。

## 14. 扩展

新增应用通常只需增加 app YAML 和 task YAML，无需修改 Python。新增平台需实现 `PlatformAdapter` canonical protocol，注册到 `platforms.registry`，覆盖 command/observe/verify_effect/release，并增加 contract、命令和 opt-in 集成测试。

新增模型测试生成器实现：

```python
class TestScriptGenerator(Protocol):
    def generate(self, requirement: str, capabilities: Mapping[str, Any]) -> TestCaseSpec: ...
```

生成结果先经 Pydantic 校验，再交给确定性 renderer；不要让模型直接拼接可执行 Python。

## 15. 常见问题

**为什么安装 Python 包后还会下载 npm 包？** 适配器使用 npx 调用官方 Midscene CLI。首次下载后由 npm 缓存复用。

**为什么命令只生成 plan？** 默认 mode 是 plan。确认风险与目标后显式传 `--mode live`。

**为什么 resume 返回 `resume_invalid`？** 当前 request/config/app/Loop/skill lock/target 与 checkpoint 不一致。使用原配置恢复，或启动新的 run ID。

**为什么纯 resume 不能带单独的 platform？** 配置式 selector 必须完整提供 platform、app、task，防止部分参数被误解或丢弃。

**为什么 skill lock 报 root 缺失？** lock 描述 skill 内容，必须同时提供实际 `--skills-root` 才能校验。

**为什么 Loop 很快退出？** 查看 `result.json` 的 `exit_reason` 和 `secondary_errors`，再检查 max runtime、failure/no-progress、登录/购买阻塞以及设备可达性。
