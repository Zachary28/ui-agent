
## 1. 项目概述

**Midscene UI Agent (Python)** 是基于 Midscene 的统一多平台 UI 自动化框架。

核心能力：
- 六大平台统一入口：Browser、Computer、Android、iOS、HarmonyOS、Vitest E2E
- 单次任务执行：连接设备、启动应用、执行操作、截图、断言
- Loop Engineering：可配置的长时间视频播放、弹窗关闭、广告跳过、剧集切换
- 分层配置管理：默认值 → 平台 → 应用 Profile → 任务 → CLI/API 覆盖
- 可恢复执行：指纹验证的 checkpoint，中断后可安全恢复
- 安全机制：弹窗/广告操作白名单限制

技术栈：Python 3.11+、Pydantic v2、PyYAML、Typer、LangGraph（可选）、Midscene CLI

## 2. 项目目录结构

关键依赖方向：interfaces → application → domain；platforms → infrastructure + domain；infrastructure → domain

## 3. 部署

### 3.1 依赖概览

**关键说明：无需手动 `npm install` Midscene。** 每个平台适配器通过 `npx -y <package>` 在首次运行时自动从 npm registry 下载 Midscene CLI 包（约 50-200 MB）。这与使用 `npx create-react-app` 的方式相同。

| 平台 | Midscene 包 | 连接方式 |
|---|---|---|
| browser | `@midscene/web@1` | Puppeteer / CDP / Bridge |
| computer | `@midscene/computer@1` | Windows RDP |
| android | `@midscene/android@1` | ADB |
| ios | `@midscene/ios@1` | WDA |
| harmony | `@midscene/harmony@1` | HDC |
| vitest_e2e | Vitest + Midscene E2E | 需 pnpm + 项目目录 |

### 3.2 系统要求

- **操作系统**：Windows 10+、macOS 12+、Ubuntu 20.04+
- **Python**：3.11+
- **Node.js**：18+（提供 npm 和 npx）
- **Vitest E2E 额外**：pnpm

```powershell

midscene-ui-agent run --platform browser --url https://example.com --goal "验证页面已加载"
```

### 常用参数

| 参数 | 说明 |
|---|---|
| --platform | 平台名称（必填） |
| --goal | 操作目标（必填） |
| --url | Browser 目标 URL |
| --device-id | Android/HarmonyOS 设备标识 |
| --mode | plan（仅生成计划）或 live（实际执行） |
| --launch-uri | 要启动的应用包名 |
| --cdp | Chrome DevTools Protocol 端点 |
| --resume | 恢复指定 run_id |
| --json | JSON 格式输出 |
| --check-dependencies | 检查平台依赖 |

### 输出产物

执行结果写入 artifacts/<run_id>/：
- plan.json — 计划模式下的执行计划
- result.json — 执行状态、步骤、错误
- manifest.json — 产物清单
- events.jsonl — 脱敏后的事件日志
- work/midscene_run/report/*.html — Midscene 原生报告
- work/midscene_run/log/ — 平台日志
- work/midscene_run/report/screenshots/ — 截图

## 5. Python API

```python
from midscene_ui_agent.api import run
from midscene_ui_agent.contracts import AutomationRequest

# 单次任务
request = AutomationRequest.model_validate({
    "platform": "browser",
    "target": {"url": "https://example.com"},
    "goal": "验证页面已加载",
    "mode": "live",
})
result = run(request)
print(f"状态: {result.status}, 运行 ID: {result.run_id}")

# 循环任务
request = AutomationRequest.model_validate({
    "platform": "android",
    "target": {"device_id": "AGYJUT3628001141"},
    "goal": "观看免费电视剧",
    "mode": "live",
    "loop": {
        "operations": {
            "dismiss_popup": {"enabled": True, "interval_seconds": 2},
            "check_playback": {"enabled": True, "interval_seconds": 5},
            "switch_episode": {"enabled": True, "interval_seconds": 300, "strategy": "next_episode"},
        },
        "exit_conditions": {"max_runtime_seconds": 1800},
    },
})
result = run(request)
print(f"退出原因: {result.exit_reason}")
```


## 6. Loop Engineering 详解

Loop Engineering 是基于 Tick 模型的循环自动化引擎。每个 tick 执行：scheduler 检查到期操作 → selector 选择一个 → 执行 → 记录状态 → exit_policy 判断是否退出。

### 6.1 支持的操作

| 操作 | 说明 | 典型间隔 |
|---|---|---|
| dismiss_popup | 关闭普通弹窗（不允许登录/购买） | 2s |
| skip_ad | 跳过广告 | 1s |
| check_playback | 验证视频是否正在播放 | 5s |
| recover_playback | 恢复播放（暂停后继续） | 30s |
| play_video | 启动/恢复视频 | — |
| switch_episode | 切换到下一集/免费集 | 300s |
| scroll_feed | 滑动到下一个短视频 | 15s |
| screenshot | 截图取证 | — |
| assert_state | 断言当前界面状态 | — |
| navigate_back | 返回上一级 | — |

### 6.2 操作配置

每个操作可独立配置以下参数：

```yaml
operations:
  switch_episode:
    enabled: true            # 是否启用
    interval_seconds: 300    # 执行间隔（秒）
    timeout_seconds: 30      # 超时（秒）
    max_attempts: 3          # 最大尝试次数
    priority: 50             # 优先级（越高越优先）
    startup: false           # 是否启动时立即执行
    on_popup: false          # 弹窗出现时触发
    on_ad: false             # 广告出现时触发
    on_stall: false          # 播放卡顿时触发
    strategy: next_episode   # 操作专用参数
```

### 6.3 全局默认值

```yaml
defaults:
  interval_seconds: 5              # 默认操作间隔
  min_operation_interval_seconds: 1  # 最小允许间隔
  timeout_seconds: 30              # 默认超时
  max_attempts: 3                  # 默认最大尝试次数
  evidence: true                   # 是否收集截图证据
```

### 6.4 退出条件

```yaml
exit_conditions:
  max_runtime_seconds: 1800        # 最大运行时间
  max_consecutive_failures: 3      # 最大连续失败次数
  max_no_progress_ticks: 5         # 最大无进展 tick 数
  stop_on_device_unreachable: true # 设备不可达时停止
  stop_on_model_error: true        # 模型错误时停止
  stop_on_login_required: true     # 需要登录时停止
  stop_on_unhandled_popup: true    # 无法处理的弹窗时停止
  disconnect_on_exit: true         # 退出时断开设备
  close_browser_on_exit: false     # 退出时关闭浏览器
```

退出原因枚举：MAX_RUNTIME、MAX_SWITCHES、MAX_SCROLLS、TARGET_COUNT、CANCELLED、MAX_FAILURES、NO_PROGRESS、LOGIN_REQUIRED、PURCHASE_REQUIRED

### 6.5 弹窗/广告安全白名单

弹窗和广告操作受白名单限制，只允许：关闭、跳过、稍后、返回。若 AI 返回登录、购买、支付、会员、提交账号信息等动作，循环立即终止并标记 LOGIN_REQUIRED 或 PURCHASE_REQUIRED。

### 6.6 典型循环场景

**免费电视剧自动连播**：

```yaml
# config/tasks/watch-free-series.yaml
profile: android.tencent-video
goal:
  category: television_series
  require_free: true
loop:
  exit_conditions:
    max_runtime_seconds: 1800
    max_switches: 3
  operations:
    dismiss_popup:  {enabled: true, interval_seconds: 2}
    skip_ad:        {enabled: true, interval_seconds: 1}
    check_playback: {enabled: true, interval_seconds: 5}
    switch_episode: {enabled: true, interval_seconds: 300, strategy: free_only}
```

**短视频自动滑动**：

```yaml
# config/tasks/short-video-loop.yaml
profile: android.bilibili
loop:
  operations:
    dismiss_popup: {enabled: true, interval_seconds: 2}
    scroll_feed:   {enabled: true, interval_seconds: 15, scroll_limit: 100}
```

## 7. 分层配置管理

### 7.1 配置优先级

```text
config/defaults.yaml                 ← 最低优先级
  → config/platforms/<platform>.yaml
  → config/apps/<platform>/<app>.yaml  应用 Profile
  → config/tasks/<task>.yaml           任务配置
  → CLI --override key=value           ← 最高优先级
```

### 7.2 应用 Profile 示例

```yaml
# config/apps/android/tencent-video.yaml
id: android.tencent-video
platform: android
extends: ../../platforms/android.yaml

app:
  name: 腾讯视频
  package_name: com.tencent.qqlive
  launch_uri: com.tencent.qqlive

ui:
  free_markers: [免费, 限免, 免费观看]
  popup_prompts:
    - "关闭普通弹窗，不要登录、购买或提交数据"
  ad_prompts:
    - "点击跳过广告或关闭广告"
  playback_markers:
    - "视频正在播放"
```

### 7.3 合并规则

| 数据类型 | 合并方式 |
|---|---|
| 标量 | 高优先级覆盖低优先级 |
| 对象/映射 | 深度合并 |
| operation | 按名称深度合并 |
| 列表 | 默认整体替换 |
| 列表追加 | 需显式声明 append: true |

### 7.4 密钥安全

所有凭据仅保存环境变量名引用：

```yaml
credentials:
  model_api_key_env: MIDSCENE_MODEL_API_KEY
  rdp_password_env: COMPUTER_RDP_PASSWORD
```

禁止在 YAML、checkpoint、事件、报告中保存 API key、Cookie、密码、WDA session、Authorization header、手机号或验证码。

### 7.5 CLI 覆盖

```powershell
midscene-ui-agent run \
  --platform android --device-id AGYJUT3628001141 \
  --profile android.tencent-video \
  --task watch-free-series \
  --override "loop.operations.switch_episode.interval_seconds=120"
```

## 8. Checkpoint 与恢复

### 8.1 保存内容

Checkpoint 写入 artifacts/<run_id>/checkpoints.sqlite，保存：
- 当前 tick 编号、已用时间
- 各操作尝试/成功次数
- 剧集切换计数、短视频滑动计数
- 播放累计时间
- 无进展 tick 数、连续失败次数
- 待执行操作
- 指纹集合

不保存：进程句柄、CLI session、Cookie、凭据、截图二进制、设备连接对象、登录状态。

### 8.2 恢复条件

恢复时必须全部匹配以下指纹（任意一项不匹配返回 RESUME_INVALID）：
- run_id、target_fingerprint
- profile_hash、config_hash
- loop_plan_hash、skill_lock_hash

```powershell
midscene-ui-agent run --platform android --device-id AGYJUT3628001141 --resume <run_id>
```

## 9. 安全约束

所有操作直接执行，无需审批流程。安全约束如下：

- 弹窗/广告：白名单模式，禁止登录/购买/支付/会员/提交账号信息
- 密钥：只通过环境变量注入
- 设备断开：退出时自动尝试断开
- 指纹校验：恢复时匹配全部指纹

## 12. 扩展新应用 Profile

2. 至少包含 id、platform、app.package_name（或 app.url）

## 13. 常见问题

**Q：模型调用失败？**
确认 .env 中的 MIDSCENE_MODEL_API_KEY 和 MIDSCENE_MODEL_BASE_URL 正确。运行 midscene-ui-agent run --check-dependencies 检查。

**Q：adb 找不到设备？**
执行 adb devices 确认设备已授权 USB 调试。Windows 上需将 ADB 目录加入 PATH。

**Q：循环提前退出？**
检查 exit_reason 字段：
- MAX_RUNTIME：正常到期，调大 max_runtime_seconds
- LOGIN_REQUIRED：遇到登录界面，检查 ui 弹窗提示词
- NO_PROGRESS：播放无进展，调大 max_no_progress_ticks
- PURCHASE_REQUIRED：遇到付费界面

**Q：如何禁用某个操作？**
在任务 YAML 中设置 enabled: false，或 CLI 覆盖：

```powershell
midscene-ui-agent run ... --override "loop.operations.dismiss_popup.enabled=false"
```

**Q：支持哪些 AI 模型？**
任何兼容 OpenAI API 的模型均可使用。在 .env 中配置 MIDSCENE_MODEL_BASE_URL 和 MIDSCENE_MODEL_NAME 即可。
